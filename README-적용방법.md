# 새벽누리 v15 — 기사 분야 · 사진 설명 · 기자 소개

기존 8개 기사 분야는 **사회 · 경제 · 스포츠 · 문화 · 국제 · 지역 · 교육·청소년 · 기획** 그대로 유지합니다.

## 이번에 추가된 기능

- Pages CMS의 기사 편집 화면에 **대표 사진 설명**, **사진 출처/촬영자**, **대체 텍스트**, **기자 소개 연결 ID**를 추가했습니다.
- 기사 대표 사진 아래에 사진 설명과 촬영자·출처가 표시됩니다. 입력하지 않은 경우 실제 기사에 허위 설명을 만들지 않습니다.
- 홈페이지 상단의 **기자 소개** 메뉴(`/reporters/`)와 기자별 소개 페이지(`/reporter/{ID}/`)를 만들었습니다.
- Pages CMS에 **공개 기자 소개** 관리 메뉴를 추가했습니다.
- 프로필을 `홈페이지 공개하기`로 설정한 기자만 소개 페이지에 표시합니다.
- 기사 `기자 소개 연결 ID`에 프로필 ID를 넣으면 기사 작성자 이름을 눌러 해당 프로필로 이동합니다.
- 소개 페이지의 왼쪽 큰 여백을 제거한 단일 열 구성을 유지합니다.
- 기존 원형 로고는 상단에 다시 추가하지 않았고, 소개 페이지의 공식 로고 영역·신문 일러스트만 유지합니다.
- `reporter_portal_url`은 실제 보안 로그인 서버를 배포한 후에만 설정합니다. 비워두면 로그인 링크는 나타나지 않습니다.

## 기자 프로필 등록 방법

1. app.pagescms.org → `dawnuri-news` → **공개 기자 소개** → 새 항목 추가
2. 공개할 이름·필명, ID(예: `reporter-one`), 역할, 담당 분야, 소개, 공개에 동의한 사진(선택)을 입력
3. 본인 동의를 확인한 뒤 `홈페이지 공개하기` 설정을 켜고 저장
4. Pages CMS → **기사 작성·수정** → 해당 기자 기사에서 `기자 소개 연결 ID`에 프로필 ID를 입력해 저장
5. GitHub Actions 배포 완료 후 사이트의 **기자 소개** 및 기사 기자명 링크 확인

## 사진 설명 입력 방법

1. Pages CMS → **기사 작성·수정** → 해당 기사 선택
2. `대표 사진` 등록 또는 확인
3. `대표 사진 설명 (대체 텍스트)`는 실제로 사진에 보이는 장면을 짧게 적음
4. `사진 설명 (사진 아래 표시)`에는 촬영 사실에 근거한 인물·장소·상황을 적음 (촬영 동의·사실 확인)
5. `사진 제공·촬영자 표기`에는 출처 및 이용 허락을 확인한 표기를 적음

## 본문 안의 사진 설명 (선택)

사진을 본문 중간에 삽입하고 한 줄 설명을 붙이려면, Markdown 본문에 아래와 같이 적을 수 있습니다. (본문 편집기에서 Markdown 형식으로 입력 가능한 경우에 한함)

```markdown
![촬영한 장소와 상황](https://example.org/photo.jpg "사진 설명: 촬영 일시와 장소 및 장면. 촬영: 기자명")
```

게시 화면에는 사진 아래에 인용부호 안의 설명이 표시됩니다. 실제 사진 주소와 검증한 문구로 바꾸세요. 대표 사진은 별도의 사진 설명 필드를 사용하는 게 가장 쉽습니다.

## 비공개 데이터 주의

**공개 GitHub 저장소에서는 `visible: false`인 프로필 JSON도 다른 사람이 열 수 있습니다.** 공개할 내용만 프로필에 적어 주세요. 로그인 아이디·비밀번호·기자별 연락처·학급·생년월일은 프로필에 저장하지 않습니다.

**기자 로그인 계정 관리와 기자 소개 페이지는 별개입니다.** 기사 프로필은 공개 정보만 다룹니다. 편집장 승인형 로그인은 별도 인증 서버(v14 기자실)를 안전하게 배포·검증한 후 사용할 수 있습니다. 이 수정본만 설치해서 실제 로그인 기능이 생기지는 않습니다.

## GitHub 적용

`github-update` ZIP의 파일들을 압축 해제하고 파일 구조 그대로 저장소 루트에 업로드합니다. 수정되는 기존 파일은 **`build.mjs`, `public/assets/style.css`, `.pages.yml`** 세 개입니다. 새로 생기는 파일은 `content/reporters/README.md`이고, 폴더를 생성하기 위한 안내문입니다.

`content/articles/`, `content/issues/`, `content/site.json`은 **절대 덮어쓰지 마세요.** 이미 작성한 원고와 발행 기록을 보호하기 위해 업데이트 ZIP에 포함하지 않았습니다.

기존 `.pages.yml`을 별도로 수정한 상태라면 새 설정과 비교하여 병합하세요. ZIP 업로드 시 기존 파일 내용 변경을 GitHub가 어떻게 처리하는지 반드시 확인하고 Commit합니다. 배포 후 `app.pagescms.org`를 새로고침하세요.
